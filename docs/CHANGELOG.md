# 網站維護紀錄（中文）

> 原則：保留品牌內容與既有視覺，優先處理實際會導致錯誤或增加維護困難的部分。

## 2026-11-03｜第一輪整理（PR #10）

| 修改項目 | 為什麼修改 | 影響 |
|---|---|---|
| HTML 的 /images、/assets、/products 等絕對路徑改成相對路徑 | GitHub Pages 專案網址可能包含 /kueitea-site/ 子路徑；原路徑可能載入錯誤 | 首頁與子頁較容易在不同網站根目錄運作 |
| 加入繁體中文 `lang`、文字替代與手機縮放支援 | 改善螢幕閱讀器與手機使用體驗 | 不改變核心版面 |
| 保留首頁入場動畫，簡化判斷 | 原本使用 document.write 與固定網域判斷，不利維護 | 站內跳轉與偏好減少動畫者跳過動畫 |
| 移除子頁不使用的相簿套件與全站未使用的 util.js 引用 | 減少多餘請求與依賴 | 原始套件檔案保留，以便回退 |
| 替首頁圖庫加套件存在檢查 | 子頁已不載入圖庫套件，需避免主程式呼叫不存在的方法 | 預防 JavaScript 執行錯誤 |
| 將第二張產品卡改為「資料準備中」 | 原連結 `products/p2.html` 尚不存在 | 避免點擊產生 404 |
| 暫時移除第三張產品卡 | `images/p3.png` 尚不存在 | 避免破圖，待取得資料再恢復 |
| 新增 `scripts/check_links.py` | 修改網頁後可快速檢查連結是否失效 | 只需 Python 標準函式庫 |
| 新增 `README.md` 與 `AGENTS.md` | 讓非工程背景的主理人與未來的 AI 開發助手容易接手 | 降低交接成本 |

## 未來工作方式

1. 先以 PR 提出可回退的修改。
2. 每次修改都寫明「改動／原因／驗證結果」。
3. 執行靜態連結檢查，再於手機與電腦測試。
4. 任何涉及品牌方向、產品真實資訊、對外聯絡資訊或正式發布的變更，先與主理人確認。
